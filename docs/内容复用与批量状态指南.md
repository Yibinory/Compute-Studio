# 内容复用与批量状态指南

新实验使用项目内容库，不再在本机为每次运行复制整份代码和所有前序运行目录。

## 文件怎么保存

```text
projects/<项目 ID>/
  code/                       可编辑的公共源代码
  tasks/<实验 ID>/files/       实验专用文件
  objects/<hash 前两位>/<hash> 唯一的文件内容
  runs/<运行 ID>/
    catalog.json              输入、输出及历史文件的 hash 引用
    control/                  已回传的控制记录与完整日志
    run.log                   日志尾部兼容文件
```

服务器也在该项目的 `objects/` 中维护内容库，并在 `_meta/objects.sqlite3` 维护 **hash → 文件路径、大小和指纹** 索引。一次准备先比较本次需要的 hash，检查对应文件是否存在；只上传缺失或无效的内容，相同内容对应多个路径时也只上传一次。共享工作目录使用同一份实际内容库。

运行中的代码使用独立副本，支持的文件系统会优先使用写时复制。前序数据是只读文件引用，`deps/<前序 ID>/` 的访问约定保留。实验结束后，工作区中未修改的代码和生成的输出也会封存为内容引用，避免长期保留每次运行的实体副本。

只读前序文件和目录用于输入，**不要在 `deps/` 中修改文件或写入新结果**。新结果应写在自己的工作区，例如 `outputs/`。普通 Python、NumPy、PyTorch 文件读取可直接使用这些路径。需要查找同目录的其他文件时，使用逻辑目录路径，不要依赖符号链接的真实目标目录。

回传只收集本节点新增或修改的输出，不再回传未改变的代码和整个前序目录。相同 hash 已在本机内容库中时也不重复下载。未被输出规则选中的生成文件仍保留在服务器内容库，直到该项目被清理；不会自动删除未声明的数据。

`0 B` 上传表示不发送新的文件内容，仍需发送清单、检查文件和执行控制信息。

大文件回传按不可变 hash 保存下载片段。网络中断或控制器更新后继续接收缺失部分，完整文件仍须通过 SHA-256 核验才会入库；损坏片段仅重传该文件，不重新执行实验。回传重试期间显示「回传中」，实验详情显示已接收字节和百分比，并保留最近一次错误供排查。字节达到 100% 后还需保存控制记录和日志，完成前后续依赖继续等待。

结果文件使用独立 SSH 传输连接，与资源监测、调度命令和其它结果传输隔离，避免一次连接重建连带打断多个任务。暂时的回传失败会自动重试；也可点击「重试回传」。不要使用「重新执行」处理已经算完、只是文件还未归档的实验。

## 选择需要的文件

实验详情提供「文件复用与输入」区域：

- **选择文件**：指定公共代码包含／排除、回传输出，以及每个直接前序的文件规则。
- **查看传输计划**：后台计算文件清单，显示引用大小、唯一内容大小，以及每台服务器还需上传多少。
- **本次上传／服务器复用／本次回传**：实际运行的增量统计。

未配置时，使用公共代码和任务文件，并引用前序**自身新增或修改的输出**，不自动递归加入前序的代码或更早依赖。

配置 `dependency_files` 时，规则可显式选取前序快照中的文件，包括它的输入，用于兼容确实需要更早输入的脚本；选多少就引用多少。某个前序配置为空数组表示只有执行顺序依赖，不传它的文件。写错文件名或没有匹配的 glob 会显示准备失败原因，不会悄悄忽略。

共享初始权重等已有内容可使用 `object_files`，例如 `{"inputs/initial/model.pth":{"sha256":"完整64位hash","size":字节数}}`。内容须已存在于本项目 `objects/`，工具按需补传至目标服务器，再以只读引用提供逻辑文件路径；不必放进数据集目录，也不会为每次运行复制完整权重。引用须与代码／任务文件路径分开，不能占用 `deps/`。脚本读取该逻辑路径即可，详见 [实验指南中的对象引用示例](实验脚本与批量配置指导.md)。

批量导入示例：

```json
{
  "experiments": [
    {
      "key": "extract",
      "name": "提取特征",
      "script": "scripts/extract.sh",
      "code_exclude": ["checkpoints/**", "scratch/**"],
      "output_files": ["outputs/features.npz", "outputs/metrics.json"]
    },
    {
      "key": "evaluate",
      "name": "评估特征",
      "script": "scripts/evaluate.sh",
      "depends_on": ["extract"],
      "dependency_files": {
        "extract": ["outputs/features.npz"]
      },
      "output_files": ["outputs/evaluation.json"]
    }
  ]
}
```

批量配置的前序 key 会自动转换为实验 ID。已有实验可使用实际 ID。字段约定：

| 字段 | 类型与默认值 | 作用 |
|---|---|---|
| `code_files` | glob 数组；省略或 null 表示全部 | 公共代码的包含规则 |
| `code_exclude` | glob 数组；默认空数组 | 公共代码的排除规则 |
| `dependency_files` | 前序 key／ID → glob 数组 | 每个前序需要的快照文件 |
| `output_files` | glob 数组；省略或 null 表示自身所有输出 | 需要回传的输出；空数组只回传日志与控制记录 |

默认排除 `.git`、虚拟环境、依赖安装目录和 Python／pytest 缓存。模型、数据等大文件应放在数据集目录或作为前序输出引用，避免放进需要独立写入的代码工作区。

SH 仍需以前台方式执行，建议 `set -euo pipefail`，以最后的退出码报告成功或失败；退出码规则、GPU／数据集环境变量及进程组中断约定保持不变，详见 [实验脚本与批量配置指导](实验脚本与批量配置指导.md)。

## 查看与整理存储

项目的「存储与复用」页提供：

1. 后台统计内容库大小、旧运行副本、引用总量及复用估算。
2. 按运行 ID 查看输入、自己的输出和旧副本大小；清单支持范围切换、分页和逐文件下载。
3. 「整理历史重复文件」将旧 `input`／`result` 实体文件纳入内容库，**保存并核验引用后**再移除重复文件。原字节、历史文件路径信息和日志保留。
4. 可同时整理选定服务器；已核验的共享工作目录按组处理一次。
5. 整理可在操作记录中中断，重新点击可继续。存在运行、准备、回传或状态未知的实验时拒绝整理。

旧实验的完整历史工作区也保留在目录清单中；新实验不会把这份完整历史自动传给后续。查看工作区快照时，展示的是本机已保存的输入与输出，未选中回传的服务器文件不在本机清单里。

内容库保留每种不同的历史内容，不会为了省空间而自动丢弃不同版本的模型或失败运行产生的独有结果。删除重复副本与删除独有成果是不同操作。

## 缓存核验与手动清理

调度前快速检查本次所需 hash 的文件存在性和文件指纹；被手动删除的文件会被发现并补传。大小、修改时间或身份变化时重新验证相关文件，不对所有缓存每次重新计算 hash。

完整缓存扫描默认每 **24 小时**进行一次，可在「调度设置」修改间隔；也可在项目存储页手动核验。自动扫描在项目没有活动实验时进行。核验操作可在操作记录中中断。

工具清理服务器上的项目时，会同时清除该项目缓存及对应索引；已检测的共享组一起更新。清理前保存需要保留的远程内容到本机内容库，避免再建立整个项目的重复归档目录。

## 批量状态操作

实验队列和项目的实验页提供「批量状态操作」。选择实验和动作后，先显示可操作数量与跳过原因，再提交：

| 操作 | 行为 |
|---|---|
| 批量中断 | 停止整个实验及子进程；尚未开始的实验直接取消 |
| 批量暂停 | 暂停排队或暂停整个运行；运行暂停仍占用 GPU／显存 |
| 批量恢复 | 恢复排队或继续原有进程 |
| 批量重新执行 | 保留旧结果，新建运行并入队 |
| 中断后安全重启 | 先中断活动实验，等待安全退出与结果回传，再入队 |

同时重试前序和后续时，先重置选中的后续，再重置前序，避免旧的成功后续锁住前序。未选中的运行中／已完成后续仍受保护；状态未知或回传失败的实验不能直接重启。

批量操作不改变全局调度开关。调度已暂停时，重新执行只入队，用户恢复调度后才开始运行。结果窗口区分「请求已提交」与实际执行状态；长时间退出或回传会在后台继续。
